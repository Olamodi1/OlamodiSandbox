Key Concepts

Nine ideas that explain how HTTP works and why it keeps changing.

The Nine Concepts

1. Client and Server

The client (usually a browser) asks for resources and the server answers. Every HTTP exchange follows this pattern.

2. Request Methods

Verbs such as GET, POST, PUT and DELETE say what the client wants to do with a resource.

3. Status Codes

Three-digit numbers like 200 and 404 tell the client whether the request worked.

4. Statelessness

Each request stands alone. Cookies, sessions and tokens add memory on top of HTTP.

5. Multiplexing and Head-of-Line Blocking

Multiplexing sends many requests at once on one connection. Head-of-line blocking is when one slow item holds up everything behind it.

6. TLS and HTTPS

TLS encrypts and authenticates traffic. HTTPS is HTTP running over TLS.

7. Headers

Name and value pairs sent with every request and response, carrying details such as content type, caching rules and cookies.

8. Caching

Reusing files the browser already downloaded so later page loads need fewer network requests.

9. Persistent Connections

Keeping one connection open for many requests instead of opening a new connection each time.

Quick Glossary

RFC
"Request for Comments": a numbered document published by the IETF. Each HTTP version is defined in one.
TCP
The reliable transport protocol under HTTP/1.x and HTTP/2.
QUIC
A UDP-based transport with built-in encryption, used by HTTP/3.
DNS
The Domain Name System, which translates a website name into an IP address.
HPACK
The header compression format used by HTTP/2.
TLS
Transport Layer Security, the encryption protocol behind HTTPS.
CDN
Content delivery network: servers around the world that deliver content close to users.
